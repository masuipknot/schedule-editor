# スケジュール編集アプリ 設計書

最終更新: 2026-10-18 / ステータス: 初版(「未決事項」は仮決定で実装を進め、後から差し替え可能な作りにする)

---

## 1. 目的と背景

業務で使っている「案件スケジュール雛形」(Googleスプレッドシート)は、O列=開始日・P列=終了日 に日付を入れると、T列以降のカレンダーに条件付き書式で色が付く仕組みになっている。

この運用は「日付 → 線」の一方向しかない。本アプリは逆方向、つまり **ガントチャートの線を操作して日付を決め、その日付をスプレッドシートへコピー&ペーストで戻す** ための補助ツールである。

- 本アプリは「日付を決める道具」であり、スプレッドシートの代替ではない
- スプレッドシートとの受け渡しは **クリップボード(TSV形式)のみ**。ファイル連携・API連携はしない

### 雛形スプレッドシートの構造(参考)

| 列 | 内容 |
|---|---|
| C / D | タスク名(C=大項目、D=小項目) |
| H | 担当 |
| O / P | 予定 開始日 / 終了日 ← **本アプリからの貼り付け先** |
| T〜 | カレンダー(S2の日付を起点に1列1日) |
| 別シート「土日以外の休み」 | 祝日・振替休日の一覧 |

タスク名(C/D列)と日付(O/P列)は離れているため、**日付の2列だけをコピーできること** が実運用上重要(→ 6章)。

## 2. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| ビルド | Vite | React公式が推奨する構成のひとつ。設定が少なく、静的ファイルとして出力できる |
| UI | React(関数コンポーネント + Hooks) | 要件どおり |
| 言語 | TypeScript(strict) | 日付・行・列のデータ構造が多く、型があるとAI生成コードの誤りを早期に検出できる |
| 祝日データ | npmの日本の祝日ライブラリ(例: `@holiday-jp/holiday_jp`)| 祝日をデータとして同梱でき、外部API不要。採用前にメンテ状況を確認すること |
| 日付処理 | `date-fns` または自前の小さなユーティリティ | 後述「日付の扱い」参照 |
| ドラッグ処理 | **ライブラリを使わず Pointer Events で自前実装** | dnd-kit等は「並べ替え」向けで、ガントの伸縮・日単位スナップとは相性が悪い |
| テスト | Vitest | 日付計算・TSV変換などの純粋関数をテストする |
| 保存 | ブラウザの localStorage | サーバーを持たず、データが利用者のブラウザ外に出ない |
| 公開 | Cloudflare(Pages または Workers の静的アセット配信)| 静的サイトとしてデプロイ。実装時点で推奨される方式を確認する |

### 日付の扱い(重要)

- アプリ内部では日付を **`"YYYY-MM-DD"` 形式の文字列** で保持する
- `new Date("2026-04-01")` はUTCとして解釈されるため、タイムゾーンによって1日ずれる事故が起きやすい。**Dateオブジェクトへの変換は日付ユーティリティ内に閉じ込め**、コンポーネントからは直接 `new Date()` しない
- 日付の加減算・差分はすべて `src/lib/date.ts` に集約する

## 3. 画面構成

```
┌─────────────── スクロールコンテナ(縦横) ───────────────┐
│ [固定ヘッダー]                                              │
│ 項目名        │開始日│終了日│ 4 │ 4 │ 4 │ 4 │ ... (月)       │
│               │      │      │ 1 │ 2 │ 3 │ 4 │ ... (日)       │
│               │      │      │ 水│ 木│ 金│ 土│ ... (曜日)     │
├───────────────┼──────┼──────┼───┴───┴───┴───┴──────────────┤
│ 要件定義      │ 4/1  │ 4/10 │ ███████████                    │
│ 要件定義の確認│ 4/13 │ 4/16 │              █████              │
│ (空行)        │      │      │                                 │
│ ...           │      │      │                                 │
│ ←── 左ペイン(横幅固定・sticky) ─→│←── カレンダー(横スクロール) ─→│
└─────────────────────────────────────────────────────────────┘
                                    [横スクロールバー:常に画面内]
```

### レイアウト方針

- **縦横スクロールするコンテナを1つだけ** 用意し、その中で
  - 左ペイン(項目名・開始日・終了日)を `position: sticky; left: 0`
  - 日付ヘッダー3段を `position: sticky; top: 0`
  - 左上の角(列見出し)は両方向 sticky
- 理由: 左右を別のスクロール領域にすると、縦スクロール位置をJSで同期させる必要があり、行ズレの原因になる。1コンテナ+stickyなら行の高さが自動的に揃う
- コンテナの高さはビューポートに合わせる(`100dvh` - ツールバー分)。これにより **横スクロールバーが常に画面下に見える**(行数が多くてもページ最下部まで行かずに横スクロールできる)

### 寸法(初期値。定数化して調整可能に)

| 項目 | 値 |
|---|---|
| 行の高さ | 22px |
| 1日の列幅 | 26px |
| 項目名列 | 250px |
| 開始日・終了日列 | 各85px |

### 描画方針(パフォーマンス)

- カレンダーを「行 × 日」のセルで描画しない(30行 × 365日 = 約1万個のDOMになる)
- 代わりに
  - **日ごとの縦ストライプ**(全行の高さを持つ要素を日数分)で土日祝のグレー背景と縦罫線を描く
  - 行ごとに1要素で横罫線(点線)を描く
  - バーは行ごとに最大1つ、`position: absolute` で `left = 日インデックス × 列幅`、`width = 日数 × 列幅` に配置
- これで要素数は「日数 + 行数 × 2」程度に収まる

## 4. データモデル

```ts
// 1行 = 1タスク。バーは開始日・終了日から「導出」されるもので、独立したデータを持たない
type Task = {
  id: string;            // crypto.randomUUID()
  name: string;          // 項目名(他の要素に影響しない)
  start: string | null;  // "YYYY-MM-DD"
  end: string | null;    // "YYYY-MM-DD"
};

type ViewRange = {
  start: string;         // カレンダー表示の初日 "YYYY-MM-DD"
  days: number;          // 表示日数
};
```

### 設計原則: 信頼できる情報源(Single Source of Truth)は `tasks` だけ

- 左ペインの日付入力も、右のバーも、同じ `task.start / task.end` を表示しているだけ
- 「バーを動かす」=「start/end を書き換える」。バー側に位置情報を別に持たない
- 状態更新は `useReducer` に集約する(アクション例: `UPDATE_NAME`, `SET_DATES`, `CLEAR_DATES`, `PASTE_CELLS`, `ADD_ROWS`)
- reducer に集約する理由: 操作の種類が多くても状態変更の入口が1か所になり、後から Undo/Redo や保存処理を足しやすい

### 不変条件(reducer で必ず守る)

- `start` と `end` は「両方 null」か「両方あり、かつ start <= end」のどちらか
- 片方だけ入力された場合は、もう片方を同じ日付で補完する(1日タスク扱い)
  - 対象は「もう片方がまだ空の状態で、片方に日付を入れた」場合のみ
- 日付が入っている行で、開始日・終了日の **どちらか一方を空欄にして確定した場合は、両方をクリアする**(`CLEAR_DATES`)
  - 理由: 上の補完ルールをそのまま適用すると、空欄にした側が反対側の日付で埋め直され、左ペインから日付を消す手段がなくなるため
- `start > end` になる入力は入れ替えて保存する

### UI上の一時状態(reducer に入れない)

- ドラッグ中の情報(どのバーを・どのモードで・元の日付・プレビュー日付)は、ドラッグ処理のフック内の state / ref で持つ
- **ドラッグ中はプレビューを表示し、pointerup で初めて `SET_DATES` を dispatch** する。こうすると1回のドラッグ=1回の状態変更になり、Undo の単位として自然になる

### 初期データ

- 空行30行
- 表示範囲: 当月1日から 120日分

## 5. カレンダー表示

- ヘッダー3段: 月 / 日 / 曜日(日本語表記: 月火水木金土日)
- **土日・祝日・振替休日・国民の休日** の列をグレー背景にする(雛形の `#CCCCCC` 相当)
- 祝日の列は、ヘッダーにマウスを乗せると祝日名をツールチップ表示
- 今日の列にさりげない目印(縦線など)
- バーの色: 雛形に合わせ `#FFD966` 系(選択中は枠線や濃い色で区別)
- 祝日判定は `src/lib/holiday.ts` に `isHoliday(date): boolean` / `holidayName(date): string | null` としてまとめ、ライブラリ依存をこのファイルに閉じ込める

### 確認用テストケース(2026年)

- 4/29(水)昭和の日 → グレー
- 5/3(日)〜5/5(火)、**5/6(水)振替休日** → グレー
- 9/21(月)敬老の日、**9/22(火)国民の休日**、9/23(水)秋分の日 → グレー

※振替休日・国民の休日は自前ロジックで漏れやすいため、ライブラリの結果をテストで確認する

### 表示範囲の拡張

- ツールバーに「表示開始日」の入力欄を置く
- バーをカレンダーの右端より先までドラッグした場合、表示日数を自動で延長する
- 開始日・終了日に表示範囲外の日付が入力された場合も、その日付が含まれるよう範囲を広げる

## 6. 左ペイン(項目名・開始日・終了日)

### 6-1. セル編集

スプレッドシートに近い「選択モード」と「編集モード」の2段階にする。

| 操作 | 結果 |
|---|---|
| シングルクリック | セルを選択(青枠) |
| ダブルクリック / Enter / F2 | 編集モード(input にフォーカス) |
| 選択中に文字を打つ | 内容を置き換えて編集開始 |
| 編集中に Enter | 確定して1つ下のセルへ |
| 編集中に Tab / Shift+Tab | 確定して右 / 左のセルへ |
| 編集中に Esc | 編集を取り消し |
| 矢印キー(選択中) | 選択セルを移動 |
| 選択中に Delete / Backspace | セルの内容をクリア |

**この方式にする理由:** 常に input を表示する方式だと、マウスドラッグが「input内の文字選択」と「セル範囲の選択」で衝突し、6-3 の行・列コピーが実現しにくい。

### 6-2. 日付入力のルール

- 入力は編集中は文字列のまま保持し、**確定(blur / Enter / Tab)時にパース** する(入力途中の "4/" などで状態が壊れないように)
- 受け付ける形式: `4/1`、`04/01`、`2026/4/1`、`2026-04-01`、`4-1`(全角数字・全角スラッシュも半角に正規化)
- **年の省略時の解釈:** 「表示開始日」から365日以内に入る年を採用する(例: 表示開始が2026/10/1なら `3/1` は2027/3/1)
- 解釈できない文字列は確定せず、セルを赤枠にして元の値に戻す
- 表示形式は `M/D`(年をまたぐ表示範囲の場合は見分けにくくなるため、ツールチップで年付きの日付を出す)
- 開始日・終了日を入れると、即座に右側にバーが表示される
- 項目名は文字列を保持するだけで、他の要素に影響しない

### 6-3. 範囲選択とコピー/ペースト

**範囲選択**

- セル上でマウスドラッグ、または Shift+クリック / Shift+矢印 で矩形範囲を選択
- 列見出し(項目名/開始日/終了日)をクリックで列全体、Shift+クリックで複数列を選択
- 対象は「項目名〜終了日」の3列のみ

**コピー(Ctrl/Cmd + C)**

- 選択範囲を **TSV**(セル間=タブ、行間=改行)でクリップボードへ書き込む
- `copy` イベントで `event.clipboardData.setData("text/plain", tsv)` を使う
- **日付は年付き(`2026/4/1`)で出力する**
  - 理由: スプレッドシートは `4/1` を貼り付けると「今年の4/1」と解釈するため、年をまたぐ案件で日付がずれる。年付きで渡し、表示形式はスプレッドシート側の書式(M/D)に任せるのが安全
- 想定する使い方: 開始日・終了日の2列を選択してコピー → スプレッドシートのO列の先頭セルに貼り付け

**ペースト(Ctrl/Cmd + V)**

- `paste` イベントでテキストを取得し、TSVとしてパースして、選択中のセルを左上として書き込む
- 行が足りなければ自動で追加する。3列目(終了日)より右にはみ出す分は捨てる
- 日付列に入る値は 6-2 のルールでパースし、解釈できないものはスキップ(貼り付け後にスキップ件数を通知)
- 1回のペースト = 1回の `PASTE_CELLS` アクション
- スプレッドシートから項目名だけ・日付だけを貼り付けて取り込む用途も想定する

## 7. カレンダー上のバー操作

### 7-1. 操作一覧

| 操作 | 結果 | カーソル |
|---|---|---|
| バーの左右端(各6px)にホバー | — | `ew-resize` |
| 端をドラッグ | 開始日 / 終了日を変更(1日単位でスナップ) | `ew-resize` |
| バー中央にホバー | — | `grab` |
| 中央をドラッグ | 期間を保ったまま左右に移動 | `grabbing` |
| バーをクリック | 選択状態にする(他の選択は解除) | — |
| 選択中に Delete / Backspace | 開始日・終了日をクリア(行と項目名は残す) | — |
| 日付のない行の空き部分をドラッグ | ドラッグした範囲で新しくバーを作成 | `crosshair` |
| バー以外をクリック / Esc | 選択解除 | — |
| ドラッグ中に Esc | ドラッグを取り消して元に戻す | — |

- 上下方向(別の行)への移動はしない
- Mac の「delete」キーは `Backspace` として届くため、**`Delete` と `Backspace` の両方を処理する**。ただしセル編集中は無視する

### 7-2. クリックとドラッグの区別

- pointerdown から **4px 以上動いたらドラッグ** と判定、それ未満で離したらクリック(=選択)
- 判定しないと、選択しようとしただけでバーが1日ずれる事故が起きる

### 7-3. 実装方針

- `pointerdown` で `element.setPointerCapture(pointerId)` を呼ぶ
  - 理由: カーソルがバーやウィンドウの外に出てもイベントを受け取り続けられる。`mousemove` を window に付け外しする古い手法より確実
- マウス位置 → 日付 の変換は1つの関数にまとめる:
  `dayIndex = Math.floor((clientX - カレンダー左端 + scrollLeft) / 列幅)`
  ※ `scrollLeft` を必ず含めること(自動スクロール中に位置がずれないため)
- 最小期間は1日。端をドラッグして反対側の端を越えようとした場合は、1日の長さで止める
- ドラッグ中はバー付近に「4/13(月)〜4/16(木) 4日間」のようなツールチップを表示する

### 7-4. 端での自動スクロール

- ドラッグ中、ポインタがカレンダー表示領域の左右端から **40px 以内** に入ったら、その方向へ自動スクロールする
- 端に近いほど速くする(例: 最大 20px/フレーム)
- `requestAnimationFrame` のループで `scrollLeft` を増減し、毎フレーム「最後のポインタ位置」から日付を再計算する
  - 理由: ポインタが止まっていても、スクロールで下の日付は変わり続けるため、pointermove だけでは更新が止まってしまう
- 右端を越えて表示範囲の最終日に達したら、表示日数を自動で延長する(5章)
